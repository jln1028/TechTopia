Introduction to Physical Computing

Start here before building your first project.

What is physical computing?

Physical computing is when software interacts with hardware. Instead of only printing text on a screen, your code can sense the environment and control real devices. With a pi-top [4], students can build systems that respond to light, sound, motion, and button presses.

Why use pi-top [4]?

The Foundation Plate makes physical computing easier by using labeled ports like D2 or A1. Students can focus on coding ideas such as input, output, events, loops, variables, and conditions without getting lost in raw GPIO pin numbers.

Digital Ports

Use ports like D0 to D7 for simple ON/OFF components such as LEDs, buttons, and buzzers.

Analog Ports

Use ports like A0 to A3 for changing sensor values such as light level, sound level, and potentiometer position.

Python SDK

Import ready-made classes from the pitop library so you can focus on solving problems and building projects.

Coding Constructs Explained

Use this section to understand the Python building blocks that appear throughout the TechTopia projects.

Imports

from pitop import LED brings in code written by someone else so you can use a device class without building it from scratch.

Why it matters: Imports let programmers reuse tools and focus on solving the problem.

Variables

led = LED("D2") stores a reference to the LED object in a variable named led.

Why it matters: Variables make programs easier to read and reuse.

Strings

Text inside quotes, such as "D2" or "Button pressed!", is called a string.

Why it matters: Strings are used for messages, labels, and port names.

Functions and Methods

led.on() calls a method. A method is a function attached to an object.

Why it matters: Methods tell a component what to do, like turn on, turn off, blink, or beep.

Sequential Execution

Python normally runs from top to bottom, one line at a time.

led.on()
sleep(1)
led.off()
Why it matters: The order of lines changes the behavior of the system.

Loops

while True: repeats a block of code forever until the program is stopped.

while True:
    led.toggle()
    sleep(1)
Why it matters: Loops keep systems running continuously.

Indentation

Indented lines belong to the block above them.

while True:
    button.wait_for_press()
    led.toggle()
Why it matters: In Python, spaces are part of the syntax.

Conditionals

if, else, and sometimes elif allow programs to make decisions.

if level < THRESHOLD:
    led.on()
else:
    led.off()
Why it matters: Conditionals make programs responsive to sensor data.

Comparison Operators

Operators like <, >, and == compare values.

Example: level > THRESHOLD checks whether the sound is loud enough.

Boolean Logic

Boolean logic combines conditions using words like and, or, and not.

if light_level < LIGHT_THRESHOLD and sound_level > SOUND_THRESHOLD:
    buzzer.beep()
Why it matters: It helps students design smarter systems with multiple inputs.

Functions You Define

You can create your own reusable function with def.

def set_lights(r, a, g):
    (red.on() if r else red.off())
    (amber.on() if a else amber.off())
    (green.on() if g else green.off())
Why it matters: Functions reduce repetition and organize longer programs.

Parameters and Arguments

In sleep(1), the value 1 is an argument. It is passed into the function.

Why it matters: Arguments let the same function do slightly different jobs.

Numbers and Math

Programs often use math to scale sensor values.

delay = 0.05 + (p / 999) * 0.95
Why it matters: Math helps convert one range of values into another useful range.

Comments

Anything after # on a line is a comment for humans, not the computer.

# optional buzzer
buzzer = Buzzer("D0")
Why it matters: Comments explain thinking and support debugging.

Event-Driven Programming

Some programs wait for an event instead of checking in a loop every moment.

button.when_pressed = led.on
button.when_released = led.off
Why it matters: Event-driven code can feel more responsive and elegant.

Debug Printing

print() shows values while a program runs.

print("Light level:", level)
Why it matters: Printing helps students observe what the program is thinking.

Glossary

Helpful vocabulary for this unit.

Input

A signal or reading that comes into the computer from a sensor or button.

Output

A signal sent out from the computer to a device such as an LED or buzzer.

Digital

A simple state, usually ON/OFF or pressed/not pressed.

Analog

A changing value across a range, such as light level or knob position.

SDK

Software Development Kit. In this unit, it is the pitop Python library used to control hardware.

Threshold

A cut-off value used to decide when something should happen.

Debounce

A short delay that helps prevent one press or sound from being counted multiple times.

Event

Something that happens, like a button press, that your program can respond to.
